## 2. Launch

Driver `scripts/run_p4.sh` runs Stage A (training, background) and Stage B (rollout, on
ckpt arrival) in one process. Stage A command, verbatim:

```bash
cd ~/td_pusht
nohup env CUDA_VISIBLE_DEVICES=2 \
    ~/miniconda3/envs/wemm-p1/bin/python -u -m patch_policy.train \
    --config configs/pusht_dino_p256_td.yaml \
    --train-seed 0 --epochs 40 --ckpt-epochs 10,20,30,40 \
    --save-dir outputs/p4_td > logs/p4_train.log 2>&1 &
```

Stage B, once per ckpt (the `0` is `rng_seed`):

```bash
bash scripts/rollout_locked_gpu2.sh \
    configs/pusht_dino_p256_td.yaml \
    outputs/p4_td/seed0/ckpt_epoch${EP}_*.pt \
    outputs/p4_td/rollout/ep${EP} \
    logs/p4_rollout_ep${EP}.log 0 \
    --num-evals 20 --num-envs 10 --train-seed 0
```

**Ckpt-arrival guard.** `wait_for_ckpt` accepts a file only when its size is
`> 400000000` B **and** unchanged across two checks 20 s apart. The 400 MB floor exists
to reject the pre-training epoch-0 ckpt, which carries no optimizer state and is ~200 MB.

### A.4 Determinism check — the n=100 run is a superset of the n=20 run

The protocol fixes scenes as `eval_seed = train_seed + i` and never resamples, so
episodes 0–19 of this run are the **same 20 scenes** as §8's ep30 rollout. Comparing
those 20 episodes across the two runs:

| check | result |
|---|---|
| seeds present in both | 20 (`0…19`) |
| episodes differing by >1e-9 | **0** |
| mean over those 20 seeds | n=20 run **0.8210**, n=100 run **0.8210** |

So the two runs agree bit-for-bit where they overlap, and the 0.8210 → 0.6149 change is
**entirely** the added scenes 20–99 — not drift, not a changed harness, not a different
noise draw. The §8 ep30 figure was an unbiased-but-noisy estimate over the 20 easiest
scenes; `final_coverage_std` is 0.4077, so n=20 carries a ±0.09 standard error.

### B.4 Determinism — all four epochs are supersets, not resamples

`scripts/check_p4_n100_superset.py` re-runs the 09-17 addendum's §A.4 check for all four epochs
instead of just ep30. It keys episodes by `eval_seed`, so the comparison is scene-to-scene.

| ep | shared seeds | agree within 1e-9 | max abs diff | mean over shared scenes (n=20 vs n=100) |
|---|---|---|---|---|
| 10 | 20 | **20/20** | 4.44e-16 | 0.4713 vs 0.4713 |
| 20 | 20 | **20/20** | 4.44e-16 | 0.5067 vs 0.5067 |
| 30 | 20 | **20/20** | 0.00e+00 | 0.8210 vs 0.8210 |
| 40 | 20 | **20/20** | 2.22e-16 | 0.7010 vs 0.7010 |

The residuals are 2–4 ULP of fp64 at cov ≈ 0.5–0.8 (one epoch came back exactly 0.0), not a
substituted scene — a different scene would land O(0.1) away, fourteen orders of magnitude above
this. So the added scenes 20–99 are **added**, and the n=20 → n=100 deltas below are an n effect.

**The deltas are not constant**, which is why the n=20 column could not be rescaled and had to be
replaced outright:

| ep | 10 | 20 | 30 | 40 |
|---|---|---|---|---|
| Δ(n=20 → n=100) | **−0.0302** | **−0.0145** | **−0.2061** | **−0.1345** |

rollout coverage keeps climbing, and it is not visible in a mean.

It establishes that the four K groups in `2026-09-19_ablation_record.md` §A.4 are on one
